# Local Audio Control v1.1.7

Исправлена команда «Следующий трек» при полноэкранном RDP: теперь переключается локальный плеер, а не удалённый сеанс.

## Причина

`NextTrack.exe` отправлял `VK_MEDIA_NEXT_TRACK` через `SendInput`. Клавиатурное событие уходит в активное окно; при полноэкранном `mstsc` его обрабатывает удалённый сеанс, поэтому локальная Яндекс.Музыка в Chrome трек не получала. Громкость и переключение выхода работали, потому что не используют клавиатуру.

## Решение

Добавлен `SmtcMedia.cs`:

- перед медиаклавишей приложение получает текущую локальную SMTC-сессию (`GlobalSystemMediaTransportControlsSessionManager.GetCurrentSession`);
- если `IsNextEnabled`, вызывается `TrySkipNextAsync`;
- при успехе медиаклавиша не отправляется;
- если SMTC недоступен, сессии нет или плеер не поддерживает «следующий», используется прежний `SendInput`;
- WinRT вызывается через отражение, поэтому сборка не требует Windows SDK и новых зависимостей;
- запрос ограничен 2 секундами; при таймауте медиаклавиша не дублируется, чтобы не перескочить два трека.

Исправление 1.1.6 (удаление подсказок клавиш после кнопок мыши) сохранено.

## Проверки

- SMTC-сессия Chrome: `TrySkipNextAsync=True`, трек сменился с «The Pages» на «Cent corps».
- Скомпилированная сборка: `TrySkipNext=True`, в журнале `SmtcMedia: next in Chrome`.
- Полный путь `NextTrack.exe` → приложение → SMTC → Chrome: журнал и смена трека.
- В полноэкранном RDP пользователь подтвердил: кнопка «Следующий трек» переключает локальную Яндекс.Музыку.
- Автотесты: локальный путь не отправляет медиаклавишу, fallback отправляет её, частичная отправка и ошибки обрабатываются.
- Установщик 1.1.7 собран и установлен; настройки и назначения Logitech сохранились.

## Ограничения

- Если плеер не публикует SMTC-сессию или не поддерживает «следующий», используется медиаклавиша; при активном RDP её результат зависит от настроек сеанса.
- Выбирается текущая SMTC-сессия Windows — так же, как для обычной медиаклавиши.
- Требования: Windows 10/11 и .NET Framework 4.8 или новее.
